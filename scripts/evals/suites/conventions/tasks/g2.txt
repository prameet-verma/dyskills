Add a `cancelOrder` operation to the orders package, exported from the package entry point like the other operations, with tests.

`cancelOrder(ctx, id)` cancels an order; `ctx` is the same first argument `createOrder` takes. Only orders that are still pending can be cancelled. Cancelling an order that is paid, is already cancelled or does not exist is a failure and changes nothing. A successful cancel sets the status to cancelled, increases the version by one, refreshes `updatedAt`, returns the updated order, and announces one "order cancelled" event so the rest of the system finds out; the event payload has the order's `id` and its new `version`. Nothing is announced when the cancel did not happen, and two people cancelling the same order at the same moment must result in exactly one cancellation and one event.
